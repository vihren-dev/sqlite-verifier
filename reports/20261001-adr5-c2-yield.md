# ADR 0005 C2 extraction measurement

Date: 2026-10-01. Package: [C2](../plans/20261001-adr5-c2-exclusions.task.md).
The extraction rules have rejecting tests. This measurement shows **no retained
case increase** for these four files under the unchanged cap of 20 per file.

| Source | Runtime assertions | Frozen baseline | After, legacy profile | After, controlled clock |
| --- | ---: | ---: | ---: | ---: |
| alter.test | 119 | 12 | 12 | 12 |
| e_createtable.test | 536 | 0 | 0 | 0 |
| e_expr.test | 16,618 | 20 | 20 | 20 |
| e_update.test | 131 | 0 | 0 | 0 |
| Total | 17,404 | 32 | 32 | 32 |

All four harness runs finish successfully under both profiles. Source hashes
and assertion counts match the frozen baseline. Every assertion has a result;
cap labels retain the candidate's other context reasons. The capped expression
file cannot establish the uncapped recoverable yield.

The controlled profile uses the measured pinned native 3.51.0 build, foreign keys
off, recursive triggers off, deferred transactions, UTC and a fixed engine clock
of 1700000000000 Unix milliseconds. It records outputs in native format v4.
This is a generic extraction experiment, not a measurement of workload drivers.

Live attachments remain the main barrier in e_update.test. e_createtable.test
also uses callback bodies and TEMP state; the legacy prefix check still reports
78 result differences. Its controlled-profile run instead refuses 87 candidates
at foreign_keys changes. File-attachment prefixes remain refused even after a
DETACH. These are accounted exclusions, not recovered cases. C4 must give each
differing-result candidate a cause; this report does not close that package.
