## Progress

- 2026-10-17: task and status files, stacked on #147 (slice 6c, PR B). Native facts
  checked on SQLite 3.51.0, one statement per line: the columns and their values for
  arrays, objects and scalars; `id` 1, 4, 9 for `[10,{"x":1},30]` and 7, 9 under the path
  `$.a.b` of `{"a":{"b":[1,2]}}`; `parent` NULL; no row for NULL and for a missing path;
  `*` shows eight columns and the hidden `json` and `root` can be named; an unqualified
  `key` beside a table column `key` is ambiguous; three arguments are the prepare error
  `too many arguments on json_each() - max 2`; a JSON failure appears only when SQLite
  scans the source (no error over an empty left table, under `WHERE 0` or `LIMIT 0`); an
  argument may read a later source, which SQLite evaluates first (refused in the model);
  `LEFT JOIN` with `json_each` works natively (refused, ADR decision).

- 2026-10-17: model. The rows (`Json/Each.lean`, `Json/JsonbOffset.lean`) were ported from
  `json.c` and checked in 955 differential cases (40,071 rows, all ten columns) against
  native SQLite; facts: `id` of an object member is the offset of its label, also for a
  scalar selected by a path that ends at a member; a scalar at a path has the path as
  `fullkey`, `path` and `root`; the root path prints as given; a label prints bare only if
  it starts with an ASCII letter and has only letters and digits; a NULL path gives no
  rows. Design: `json_each` sources come after the tables (`Query.functions`, joined by
  `Query.source` in `QueryFunctions.lean`; the tables are `Query.tableSource`), so the join
  laws of tables keep their form (`Query.source_single` and `Query.source_none` add the
  premise of no `json_each` source); a table after `json_each` is the restriction
  `table-after-function`. Resolution in `Resolution/FunctionSources.lean`
  (`splitSources`, `resolveFunctions`, `resolveSources`), with the restrictions
  `table-function`, `function-join` and `later-source-in-arguments` and the prepare error
  `PrepareError.tooManyEachArguments`; `Source.hidden` hides `json` and `root` from `*` and
  `x.*`. A query in which a `json_each` may fail over its input rows is unsupported for that
  data (`eachJsonReady`); `NoWrites` also excludes queries with `json_each`. The frontend
  maps a table-valued function with its arguments, and now maps a fallback keyword such as
  `key` as a column name (`IDENTIFIER_TOKENS`): the parse tree keeps the keyword's own
  symbol, which refused `SELECT key ...` before. Authored cases
  `conformance/authored_json_each.py` (16, all AGREE; 2 prepare errors), mutants
  `conformance/json_each_mutants.py` (6, in the JSON measurement), corpus writer
  `conformance/json_each_evidence.py` (corpus 24).
