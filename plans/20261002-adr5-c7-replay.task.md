# ADR 0005 C7: replay tiers and frozen generic baseline

Created 2026-10-02. Status: DONE.
Status: [progress](20261002-adr5-c7-replay.status.md).
Spec: [ADR 0005](../docs/adr-0005-conformance-corpus-scale.md), sections 3.3–3.5
and package C7. The [C6 freeze](20261001-adr5-c6-freeze.task.md) supplies the
immutable membership and validated evidence; it is complete at `3ce0820b`.

## Observable outcomes

The conformance phase selected by actual `just test` loads the final frozen v4
generic corpus and retained synthetic workload through their ordinary validated
loaders. It replays every final authored case, including the issue boundaries,
every synthetic case, and a bounded deterministic upstream sample. It checks
fresh native observations under each exact profile and current model
classification. `DISAGREE` and `HARNESS_ERROR` fail; unsupported behavior stays
explicitly unsupported and never becomes agreement.

Sample selection has a declared stable identity, is reproducible for unchanged
frozen inputs, and is independent of native acceptance or model verdicts. Its
report binds the corpus and synthetic digests, selected case identities, policy,
denominators and verdicts. The sample does not change corpus membership or the
C6 acquisition policy. The conformance replay phase completes within 60 seconds
with a configured timeout on the supported native platforms. Measurement names
the timed phase; cached Nix success or compilation time is not presented as a
fresh replay measurement. No final case count or quota is assumed before C6.

The full model suite remains an explicit check and continues to run in CI and
release/package checks. The pre-C7 239-test model suite took 220.79 seconds;
selecting a development sample must not remove its native, compiled, kernel,
mutation, storage, profile, fidelity or historical compatibility checks. Flake
checks and the ordinary Nix entry point expose consistent targets. Fresh host
checks retain their ownership and do not duplicate the delegated conformance
suites against the shipped runtime.

`just conformance-progress` uses all frozen generic v4 cases, with their bound
manifest, shard, profile and retained evidence identities. It reports verdicts
and denominators per part, feature and shard, alongside existing per-case and
requirement output. Part and shard denominators partition the full corpus;
feature labels can overlap and keep their recorded provenance scope. Every one
of the 3,500 requirement inventory rows remains visible, including zero rows;
aliases within one case count once. Scenario counts and source-file feature
labels do not claim complete requirement coverage or model support.

A retained generic baseline identifies the actual frozen corpus, requirement
inventory, current frontend/harness and compiled runtime, with exact counts and
limitations. Historical saved reports and frozen v1–v3 evidence remain intact.
Core commands and CI require no private workload. The existing external workload
commands retain their separate completion gate.

## Behavioral verification

Checks exercise selection with reordered inputs and changed refusal/verdict
flags, proving mandatory authored/synthetic inclusion, a bounded upstream
denominator and stable selected identities. Actual frozen inputs are loaded,
natively replayed and classified through the development command path under
the 60-second bound. Tampered digests, profiles or retained evidence fail through
the shared loaders; a selected disagreement or harness failure fails the tier.

Full progress checks use every frozen record exactly once and verify part/shard
totals, overlapping feature counts and all requirement rows. Unsupported cases,
zero rows and duplicate requirement aliases keep their intended counts. The
retained baseline is regenerated from the bound inputs and identifies its scope.

CI routing checks prove that test and package scopes retain the full suite.
Real Nix dependency identity checks cover the new sample, full model and shared
inputs: frozen corpus or replay implementation changes invalidate dependent
targets, while full-only historical/test inputs do not unnecessarily invalidate
the sample. Host routing retains all source-owned checks. Document checks and
the relevant full model, extraction and Nix checks pass with bounded timeouts.

## Tricky points and sources

`justfile` currently builds the entire `tests` attribute set, and
`tools/ci_checks.py` invokes `just test` for CI's test scope. Default development
selection, the explicit full recipe, package dependencies and CI invocation
must remain consistent. `build-support/tests.nix` owns independent immutable
test results; `build-support/default.nix` and `nix/flake.nix` expose them without
another local cache. The existing full target is preserved.

The host ignore list predates several ADR 0005 modules. Thirty conformance
modules are currently delegated to Nix, but `conformance_axioms_test.py` and
`conformance_native_test.py` remain source-owned. A blanket exclusion of every
conformance-marked test would lose those checks. Shared pytest support and
runtime dependencies are checked by `tests/test_nix_test_targets.py`,
`tests/test_source_identity.py` and `tests/test_ci_checks.py`.

Reuse `conformance/{corpus,corpus_shards,corpus_evidence,progress,
requirement_coverage,workload}.py`. Loaded record order follows the verified
ordered shard manifest; shard counts can associate verdicts without adding
fields to frozen case payloads. Progress currently defaults to v3 and lacks
part/feature/shard aggregation. Its raw `byRequirement` compatibility output
and stable resolved requirement matrix remain distinct.

The native profiles currently have no production-model capability, so many v4
cases may remain unsupported. Native replay still checks the retained outputs;
the full suite continues to check supported compiled/kernel behavior. New model
semantics and C8 mutants are separate work. C6 freezes 1,264 cases with complete
fidelity triage; C7 measures replay timing and retains the final baseline views.
