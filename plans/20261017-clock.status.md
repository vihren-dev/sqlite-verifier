## Progress

- 2026-10-17: task and status files, stacked on #151 (slice 6e1, PR B). The recorder's
  `NativeClock` supplies Julian-day milliseconds in SQLite's date range (Unix
  milliseconds from -210866760000000 to 253402300800000).

- 2026-10-17: implementation of pull request A (one commit; test-full, test-nix and
  test-scheduled pass).
  - Model: `ClockText.lean` (keyword text at a Julian-day millisecond clock, checked
    differentially against native SQLite at every boundary, with `ClockTextExamples.lean`),
    `ClockSubstitution.lean` and `StatementClock.lean` (a statement at a clock value),
    `StatementClockLaws.lean` (a statement that reads no clock is unchanged),
    `Resolution/ClockCell.lean`, `Resolution/ClockRows.lean` and
    `Resolution/ClockRowRules.lean` (INSERT cells that read the clock, filled per
    statement), `Resolved.Statement.clocked`, and `StatementStep.lean` (the former
    execution). `SqlExecution.lean` runs `runSql` over `scriptAtClock`;
    `ProfileExecutes.evaluated` takes a clock assignment and `SupportedSql` holds for every
    one; `runSqlAt_of_readsClock`, `ProfileExecutes.result_of_readsClock` and
    `SchemaClock.lean` keep the existing proofs. ADD COLUMN with a time default fails on a
    populated table (`ExecutionError.nonConstantColumnDefault`), and resolution admits it.
    `ClockExamples.lean` runs scripts at clock assignments. The restriction `time-value`
    is gone.
  - Conformance: `Case.clocks` and `PredictInput.clocks` (Julian-day milliseconds), the
    controlled-clock profile is in the model's scope, ADD COLUMN's RAISE output name for
    a time default. Authored cases `conformance/authored_clock.py` (9, all AGREE),
    mutants `conformance/clock_mutants.py` (4) in the JSON measurement, corpus writer
    `conformance/clock_evidence.py` (corpus 26).
  - With the controlled clock in scope, the upstream case `expr2:expr2-1.4.1:5`
    (`SELECT (0 IS NOT FALSE) FROM t0`) showed that resolution gave `no such column` for
    `FALSE`; SQLite reads an unquoted `TRUE` or `FALSE` that names no column as 1 or 0.
    The syntax does not keep bracket or backtick quoting, so the model cannot tell
    `[false]` (no such column) from `false`; the new restriction `boolean-name` refuses
    such a name instead of a wrong prediction.
  - Mutant anchors and model inputs of the execution moved to `StatementStep.lean`
    (`algorithm_mutants`, `obligation_mutants`, `row_write_mutants`, `resolve_mutants`,
    `mutation_check`, `instrument_model`, `tests.nix`). Frozen version 4 cases gain empty
    clock values in their comparisons. `test-full` passes (model suite 330 s).
