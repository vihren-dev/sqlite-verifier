Created 2026-10-06. Status: DONE on 2026-10-07.

## Required outcomes

Lean 4.34.1 is the only toolchain used to build and run the verifier, its
proof examples, both kernel gates and the conformance classifier. The Nix
pins identify the official macOS arm64 and Linux amd64 archives by their
verified SHA-256 digests. A build cannot silently select an older Lean release.

The current skip-trusted patch applies to lean4export v4.34.0, which builds
and executes under Lean 4.34.1. Replacing that exporter is separate work.
Both checkers use the current kernel replay API, with no deprecated alias.
Library propositions and example contracts retain their meanings.

Source, installed-runtime and CI invocations retain their documented
statuses and exit codes, including successful verification, checked
refutation and refusal of invalid proofs. The installed runtime contains
the upgraded Lean tools. A reviewed release publishes that runtime after
both supported platforms pass their acceptance checks.

Record the upgraded patched-exporter baseline for the small successful
example, checked refutation and Atuin example. It identifies the inputs,
runtime, exported bundle hashes and resulting statuses so a later exporter
replacement can compare the same artifacts under the same toolchain.
Current installation, execution-profile and runtime documentation states
the upgraded version. Historical ADRs and measurements retain their dates
and original versions.

## Behavioral verification

- Verify the actual Lean and Lake versions in each built runtime on macOS
  arm64 and Linux amd64, as well as the pinned archive identities.
- Compile the public library, both checkers, the conformance classifier and
  all example proofs under the upgraded runtime.
- Run the kernel and bundle attack suites. Invalid bodies, wrong statements,
  sorry, forbidden axioms, unsafe or partial proofs, and modified protected
  inputs remain refused. A checked refutation retains exit code 2.
- Run the Atuin, CLI, model, upstream and full test targets. Existing admitted
  cases retain their results. Frozen corpus v1–v5 bytes remain unchanged.
- Run the Nix source-identity, infrastructure and extracted-installation
  checks on both supported platforms. Installed commands use the runtime's
  Lean tools, without a dependency on a developer checkout or toolchain.
- Record the three patched-exporter baselines after actual preparation and
  bundle verification on both platforms. Statuses match their existing
  acceptance cases.
- Publish the upgraded release only after its required checks and final
  owner review. Retain release links and archive digest evidence.

Every test command and subprocess has an explicit timeout. `just test`,
`just test-full`, `just test-nix` and `just package` own the corresponding
checks; cached builds do not replace installed-runtime execution evidence.

## Constraints and relevant source

`lean-toolchain` and `build-support/lean-toolchain.nix` must agree exactly.
`build-support/lean4export.nix` owns the patched source pin and executable.
`lakefile.toml` consumes that source as a path dependency. The runtime
assembly and Nix source selection must include the same toolchain and
dependency as the checkers use.

`ProofChecker.lean` and `BundleChecker.lean` replay declarations; their
API update is a trust-relevant change requiring final owner review.
`GateCore.lean`, structural inputs, allowed axioms and approved baseline
semantics retain their meaning. Kernel or dependency compatibility failures
must be resolved explicitly, rather than bypassed by selecting an older
toolchain or weakening proof acceptance.

The policy's two-week window ends on 2026-10-08 for the 2026-09-24 release.
If the target slips, the status file records the cause and remaining work.
