## Outcome

1. **Clock input.** Each statement of a script sees one clock value, a 64-bit integer in
   SQLite's Julian-day milliseconds (what the VFS method `xCurrentTimeInt64` returns); within
   a statement it does not change. The execution semantics takes a clock assignment, one
   value per statement position, as an input.
2. **Verification target.** `ProfileExecutes` relates a script and a starting database to
   the outcome of every clock assignment (owner decision 8), so the obligations of
   `VerificationConditions` hold for every clock value of every statement, also where
   SQLite's date code fails. `Contract.lean` does not change. The supported-subset check
   `SupportedSql` holds for every clock assignment. A script without time keywords and
   without a `CURRENT_TIMESTAMP` default has the same outcome for every clock assignment,
   and a lemma states it, so that existing proofs keep their form.
3. **Keywords.** `CURRENT_TIME`, `CURRENT_DATE` and `CURRENT_TIMESTAMP` give the
   statement's clock value as TEXT, as SQLite formats it (`HH:MM:SS`, `YYYY-MM-DD`,
   `YYYY-MM-DD HH:MM:SS`), in every expression context that the model has (queries, `SET`
   values, `VALUES` items, conditions, `RETURNING`), and give what SQLite gives for clock
   values outside its date range.
4. **Default.** A column with `DEFAULT CURRENT_TIMESTAMP` (also `CURRENT_DATE` and
   `CURRENT_TIME`) gives an omitted `INSERT` value the statement's clock value as TEXT,
   stored with the column's affinity. `ALTER TABLE ... ADD COLUMN` with such a default is
   SQLite's error on a populated table (`Cannot add a column with non-constant default`)
   and is admitted on an empty one, as SQLite does (checked natively).
5. **Registry.** The restriction `time-value` leaves the registry; no form of the time
   keywords stays refused by it.
6. **Evidence.** Authored coverage cases, recorded by the recorder under a controlled clock
   (ADR 0005, section 3.2), agree with native SQLite 3.51.0 and have kernel proofs; each
   mutant below changes a verdict; the verdict counts of the claimed corpora do not go
   down. Existing claims keep agreeing.

## Tests

- Lean examples: the text of each keyword at clock values at day, month, year and leap-year
  boundaries, at the start and end of SQLite's date range, and outside it; the lemma for
  scripts without time forms on an example script.
- Authored coverage cases (native SQLite under the controlled clock as the oracle): each
  keyword in a query without FROM, in `WHERE`, in `SET`, in `VALUES` and in `RETURNING`;
  two statements of one script that see different clock values; a `CURRENT_TIMESTAMP`
  default on an omitted value, with each affinity; ADD COLUMN with the default on an
  empty and a populated table; the upstream cases that read the clock and now agree are
  the second check.
- Mutants, each changing the verdict of an authored case: one clock value for all
  statements of a script; `CURRENT_DATE` with the time; seconds rounded instead of
  truncated; the default evaluated at resolution instead of per statement.

## Key points for the implementer

- **Where values are fixed today.** Resolution folds a `VALUES` item and a constant `SET`
  value to a literal (`constantValue`, `assignedExpression`), and #130 evaluates an omitted
  value's default at resolution. A clock-dependent value cannot be fixed there; it needs a
  form that the execution fills with the statement's clock value. `Resolved.Expr.eval`
  takes no clock today.
- **Contract shape.** `ProfileExecutes.result` states that the outcome is `runSql`'s; it
  becomes a statement about some clock assignment. Its users (`SqliteVerifier`
  demonstrations, `examples/atuin`) must keep working, through the lemma of outcome 2.
- **Date code.** SQLite turns the Julian-day milliseconds into text with `computeYMD_HMS`;
  a value at or below zero, or beyond its date range, makes the date code fail or give
  NULL. Check every boundary natively. The recorder's `NativeClock` refuses values outside
  SQLite's date range; a scratch copy of it can supply them for probing, but the corpora
  stay within the range.
- **Conformance.** Records of a controlled profile store `clockUnixMilliseconds` on each
  trace event; the conformance case must pass them to the model as the clock assignment.
- **Cost.** Kernel proofs of clock text are larger; keep the cases small and measure
  `tests.model`.
