# ADR 0005 C6: frozen shards and external workloads

Created 2026-10-01. Status: IN PROGRESS.
Status: [progress](20261001-adr5-c6-freeze.status.md).
Spec: [ADR 0005](../docs/adr-0005-conformance-corpus-scale.md), sections 3.3–3.6
and package C6. C0–C5 provide the recording, profile, fidelity and storage primitives.

## Observable outcomes

Corpus v4 contains the final generic authored and upstream membership, with
statement outputs, typed parameters and explicit established profiles. Each
source has a compressed shard. A versioned manifest binds the ordered shards,
counts, digests, native/storage formats, execution profiles, source files,
feature metadata, extraction policy and sampling identities. Frozen v1–v3
artifacts remain unchanged and readable. Unsupported model behavior never agrees.

Before membership freezes, native cases address the relevant boundaries from
issues [14](https://github.com/vihren-dev/sqlite-verifier/issues/14) and
[18](https://github.com/vihren-dev/sqlite-verifier/issues/18): added-column defaults,
NOT NULL on empty/populated tables, default affinity and rejected ADD forms;
valid SQLite definitions outside the model versus actual invalid definitions.
They record native truth without changing production semantics. Requirement
counts retain all 3,500 inventory rows and distinguish new evidence from support.

The manifest names the exact upstream file catalog and hashes. Acquisition has
no per-file case cap. Declared loop-generated expression cohorts use fixed
test-name-prefix sampling, with selected identities retained. Every runtime
candidate keeps all exclusion and sampling reasons. Fault, authorizer,
corruption, WAL, URI, BLOB-handle and FTS files retain explicit file exclusions.
Every new Tcl/native fidelity mismatch has an evidence-backed cause before
freezing. Corrected tracing determines yield; historical accepted candidates
are not assumed reproducible under the new rules.

External workload commands accept a directory containing a SQL inventory,
schema/query files and a measured profile. Recording produces complete typed
outputs and a frozen workload shard/manifest. Replay and progress accept that
location and reject changed source files, profile, format, count or digest.
The inventory accounts for every reached statement; an error cannot silently
hide a remaining statement or parameter row. Existing `record_sql` remains the
flexible primitive under the directory convenience path.

A neutral synthetic workload in this repository proves the same mechanism:
parameterized statements, a transaction, a trigger and a foreign key with a
cascade. A combined report can include generic and external records. No real
workload SQL, names, profiles or results enter the core. This mechanism is not
the actual-workload completion gate.

Each new expanded case is at most 1,000,000 bytes, including any retained old
selection. Current compressed shards fit 25 MB and retained corpus versions fit
60 MB. If a budget overflows, fixed-hash release-asset storage is required.
All final v4 shards pass fresh native replay under their exact profiles.

## Behavioral verification

Tests load the new per-source shards and legacy single-file corpora. They refuse
unknown format/storage versions, malformed counts, duplicate shard paths/names,
escaping paths, corrupt payloads, and undeclared or conflicting profiles.
The final generic manifest and every shard are bound and natively replayed.
Budget checks use actual compressed bytes and expanded logical-case sizes.

Real Tcl tests cover uncapped acquisition, prefix sampling and retained multiple
reasons, plus file exclusions. Retained extraction reports identify every source
and candidate. Sample selection is independent of later native acceptance.
New native boundary cases have concrete expected outcomes, and remain explicitly
unsupported where the production model has no capability.

Synthetic workload recording/replay runs through the actual directory command
path. Checks assert parameter types, result shape/rows, trigger/cascade state,
direct counts and committed state. Negative tests change SQL, profiles, formats,
digests and inventory entries, supply malformed parameters, and leave statements
unexecuted after an error. Hermetic model/upstream suites and document checks
pass with configured timeouts. The later C7 package owns replay tiers and the
60-second development sample; C6 provides their frozen inputs.

## Tricky points and sources

Reuse `native_record`, `execution_profile`, `native_storage`, `corpus`,
`requirement_coverage`, `authored_cases` and the Tcl pilot. Corpus version, Lean
case format, native acquisition version and snapshot storage version are separate
identities. Declare their actual values; a corpus version does not upgrade old
observations. Profile options stay exact. Native SQLite uses the same pinned
Clang on both CI platforms; C5's Linux check proves complete option and evidence
equality. The real workload's driver builds and effective runtime limits are
measured separately (issue [17](https://github.com/vihren-dev/sqlite-verifier/issues/17)).

`e_expr.test` has callback registration with no reset, so its current candidates
remain excluded even when sampled. `expr.test` supplies pure SQL arithmetic.
Time-function sources need a controlled clock; changed clock inputs retain their
refusal. Re-record generic evidence through the current extractor instead of
appending old output-free cases with `refresh_corpus`. Keep all historical
artifacts as evidence and keep private workload information outside the core.
